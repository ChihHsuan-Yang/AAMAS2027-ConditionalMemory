A long-horizon agent accumulates far more experience than is useful for any particular future task, and something must decide what to keep. The prevailing answer scores each stored item by how useful it is and keeps the highest-scoring ones, treating usefulness as a property of the item. That the same memory serves one future task and not another is already observed; what is missing is a signed per-item measurement of it, replicated, priced, and compared across ways of writing the same experience down. We evaluate memory conditionally instead, asking what each stored experience is actually useful for. For a memory from a past episode and a later task, we re-execute a frozen agent with and without that memory available and record the signed change in task reward, holding the model, cluster, decoding, context budget and scoring fixed between arms.

On LongMemEval-V2, useful memory is sparse. A naturally occurring memory bears on a median of one future task out of hundreds, so one global score averages a large effect over overwhelmingly many inert pairings, and a design pairing memories with tasks indiscriminately measures almost nothing. Where a memory does bear on a task it helps substantially, against a matched control drawn from the same memories. Generic embedding similarity locates that benefit poorly, while a content criterion asking whether the memory carries what the task needs locates it well. How an experience is written down also matters: aggressive summarization and structuring remove the benefit that raw experience retains.

We pair every utility measurement with the full cost of forming, storing, retrieving and exposing memory. Counting exposed tokens alone makes compression look several times more efficient; charging each representation for writing itself erases that advantage. We extend the protocol to software-engineering and scientific procedural settings, and release the Conditional Memory Utility Dataset.
